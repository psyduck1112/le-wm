# le-wm 在 LIBERO 上的诊断方案(由易到难)

> **目的**:le-wm 在 LIBERO 上表现不佳时,判断瓶颈到底在哪一个环节,而不是笼统地说"le-wm 能力有限"。
> **核心方法**:**oracle 替换 / 上界探测** —— 把流水线里的某一个环节换成"完美版本",看性能恢复多少。哪个环节换成完美后任务成功率跳上去,瓶颈就在那。
> **使用方式**:本文档是给实现方(工作站 Claude)的交接说明。每个探测包含:目的 / 流程 / 输入输出 / 判读标准 / 实现要点 / 工作量。建议**严格按由易到难的顺序执行**,前面的探测能排除掉后面的嫌疑,省力。

---

## 0. 流水线心智模型

le-wm 的推理链路:

```
观测图像 → [1.编码器encoder] → emb → [2.单步预测器predictor] → 开环rollout → [3.cost函数] → [4.CEM/Gradient规划] → 动作
                                                                       ↑
                                                  [0.数据 / 任务 / goal设定 / 集成bug]
```

每个探测单独把一个环节理想化,锁定它是不是真凶。最终用决策表(见文末)汇总结论。

**实现前先确认的 le-wm API(读 `le-wm/jepa.py`)**:
- `encode(img) -> emb`(ViT cls token → BatchNorm projector,~192维)
- `predict(emb, action) -> next_emb`(单步)
- `rollout(emb0, action_seq) -> emb_H`(自回归 H 步,规划时用)
- `criterion` / `get_cost`(MPC cost = `||rollout终点emb - goal_emb||²`)
- 训练配置 `num_preds=1`(**只训单步**,这是后面探测 C 的关键前提)

**LIBERO 侧需要的钩子**:
- 真值状态:`robot0_eef_pos`(末端位姿)、`robot0_gripper_qpos`(夹爪)、物体 pose —— 从 env 的 state / obs dict 直接取,无需标注。
- 模拟器存档/读档:LIBERO 底层 MuJoCo,支持 `get_sim_state` / `set_sim_state`(或 `env.sim.get_state()` / `set_state()`)—— 探测 E 需要。

## 前置:排除"伪装成模型弱"的非模型原因(必须最先做)

这些不排除,后面所有诊断都可能把锅扣错。

1. **任务设定匹配吗?** LIBERO 是语言条件、长程、多任务操作;le-wm 是 **goal-image 条件的单任务 MPC**。确认:
   - 给 le-wm 的 goal 是一张目标帧图像吗?这张图歧义大不大(末端位置无所谓 / 只看物体)?goal 图歧义 = cost 从根上错,与模型能力无关。
2. **训练收敛了吗?SIGReg 塌缩了吗?** 看 embedding 的**特征值谱**(eigenvalue spectrum)。谱塌成少数几维 = encoder 没学到东西,是训练问题不是能力问题。
3. **集成 bug**:frameskip、action 归一化/维度(LIBERO 7维:delta EE 6 + gripper 1)、图像预处理、坐标系是否与 le-wm 数据管线一致。
4. **训练分布内的开环预测质量**:先在 le-wm **自己的训练数据**上看单步/几步预测准不准。连训练分布内都不准 → 不是 LIBERO 的问题,是模型/训练没就绪,**先别碰 LIBERO**。

---

## 探测 1【易】规划预算够不够?(CEM budget probe)

**目的**:排除"模型其实够用,只是 CEM 搜不动"。

**流程**:
1. 固定 le-wm 模型不变。
2. 把 CEM 预算拉爆:`num_samples` ×5(300→1500)、`n_steps` ×3(30→90),topk 相应放大;或换 gradient solver 增加迭代数。
3. 跑同一批评测 episode,比较成功率。

**判读**:
- 成功率明显跳 → **瓶颈是规划预算**,模型够用。可考虑更强 solver / warm-start(后续 td_jepa actor 改造可在此发力)。
- 纹丝不动 → 排除规划,继续往下。

**工作量**:极小(只改 config,无新代码)。**第一个做。**

---

## 探测 2【易】cost 函数指对方向了吗?(cost monotonicity probe)

**目的**:查规划目标本身。**哪怕预测器完美,如果 cost 指错方向,规划照样失败。**

**流程**:
1. 取若干条**已知成功**的轨迹(专家或人工成功 rollout)。
2. 沿轨迹逐帧计算 `cost_t = ||encode(frame_t) - goal_emb||²`。
3. 把 `cost_t` 对"任务真实完成进度"(0%→100%,可用阶段标签 / 与目标物体距离近似)画曲线。

**判读**:
- cost 随进度**单调下降**,完成时最低 → cost 没问题。
- cost **非单调 / 中途出现更低的"假谷" / 完成点不是最低** → **cost 度量有缺陷**(goal-image MSE 在操作任务上不可靠:目标图含大量任务无关像素,emb 欧氏距离 ≠ 任务距离)。这不是模型能力问题,改 cost 即可。

**输出**:每条轨迹一张 cost-vs-进度曲线 + 一个单调性指标(如 Spearman 相关、或"假谷"计数)。

**工作量**:小(无需训练,只前向编码 + 画图)。

---

## 探测 3【中】表征够不够?(linear probing)

**目的**:检验 encoder 有没有把**任务相关信息**编进 emb。

**原理**:用一个**故意做得很弱**的读取器(线性 / 最多 2 层 MLP)从冻结的 emb 回归真值状态。probe 弱 = 它没能力自己"算",只能"读" emb 里现成的信息。线性就能读出 → 信息清晰可解码;弱 probe 都读不出 → 信息没进 emb。

**流程**:
1. **冻结** le-wm encoder,当固定特征提取器。
2. 数据集:大量 (frame, 真值state) 对。真值 = `robot0_eef_pos` + `robot0_gripper_qpos` + 物体 pose(从 LIBERO env state 取,零标注成本)。
3. 在 `emb = encode(frame)`(冻结)上训一个 **linear / 2层MLP** probe → 回归真值。
4. 看**测试集**回归误差。

**判读**:
- probe 误差小(能准确还原物体/末端位姿) → 信息在 emb 里且可线性解码,**encoder OK**,瓶颈在下游。
- probe 误差大(怎么都还原不出) → **encoder 表征能力不足(根本性硬伤)**,如 ViT-tiny 容量 / SIGReg 正则在精细操作上不够。td_jepa 帮不上这种,需换更大 encoder / 更强表征。

**输出**:各真值字段(eef / gripper / object)的 probe R² 或回归 RMSE。

**工作量**:中(训一个小 probe,几分钟级)。**不碰 le-wm 核心代码。**

---

## 探测 4【中】数据 vs 模型?(BC baseline 对照)

**目的**:把"数据不够"和"le-wm 链路不行"彻底分开。

**流程**:
1. 在**同一份 LIBERO 数据**上训一个普通 behavior cloning(可直接复用 le-wm encoder + 一个动作头,或独立 BC)。
2. 比较 BC 成功率 vs le-wm-MPC 成功率。

**判读**:
- BC 能成、le-wm-MPC 不能 → 数据是够的,**问题 100% 在 le-wm 的"世界模型 + 规划"链路**(由探测 C/D/E 定位具体段)。
- BC 也崩 → **数据覆盖/任务难度问题**,不是 le-wm 特有的锅。

**工作量**:中(训一个 BC)。性价比高,**强烈建议早做**,一刀切开数据 vs 模型。

## 探测 5【中】单步动力学会复合发散吗?(multi-step open-loop error)

**目的**:量化"复合误差"。**这与训练验证集不同** —— 训练 `num_preds=1` 只测 teacher-forcing 单步;规划用的是自回归多步,误差会滚雪球,训练从没优化也没测过。

**两种模式的区别**:
```
训练/验证(teacher forcing,单步):  真emb_t →pred→ 对比真emb_{t+1}     输入永远是真emb,误差小 ✓
探测5(开环,自回归):  真emb_0 →pred→ emb_pred_1 →pred→ emb_pred_2 ...  输入用自己的预测,OOD,误差复合放大
```
预测器只在干净真 emb 上训过;从第 2 步起输入是带误差的 `emb_pred`(分布外)→ 预测更差 → 雪球。**因此可能单步验证误差极小,但 k=3,4 步开环误差爆炸。**

**流程**:
1. 取真实轨迹,真起点 emb_0 + 真动作序列。
2. **开环自回归** rollout k 步:每步把上一步的预测当输入,得 `emb_pred_k`。
3. 同时把**真实第 k 帧**编码得 `emb_true_k`。
4. 测 `||emb_pred_k - emb_true_k||`(可归一化)随 k 的曲线,k=1..H。

**判读**:
- k=1,2 就快速发散 → **单步动力学不准 / 复合误差严重**,le-wm 单步预测器在操作任务上的硬伤。→ 多步预测(`num_preds>1`)或 TD 后继价值(TD-MPC)可缓解。
- 多步仍稳 → 预测器没问题。

**输出**:误差-vs-k 曲线(多条轨迹平均 + 方差)。

**工作量**:中(纯前向,无训练)。

## 探测 6【难】给完美动力学,规划能成吗?(oracle-simulator planning,上界)

**目的**:把"预测器烂"的嫌疑,从"encoder 烂 / cost 烂"里彻底切开。给规划一个**完美的动力学模型 = 真模拟器**,看 le-wm 剩下的部分(encoder + cost + 规划)够不够。这是**直接判决**,比探测 5 的间接证据更硬。

**关键澄清**:规划时 CEM 试的是**还没执行的假设动作序列**,世界上不存在对应"真实未来帧"。所以 oracle 动力学 = **用模拟器真的走一遍**(需要存档/读档分叉),不是 teacher forcing。

**le-wm 正常 MPC 闭环**:
```
1. 真状态 s_t → 拍图 → encode → emb_t
2. CEM 撒 N 条候选动作序列(每条长 H)
3. 每条候选:用【le-wm 预测器】在潜空间脑补 H 步 → emb_H        ← 要替换的就是这步
4. cost = ||emb_H - goal_emb||²
5. CEM 留 top-k,重拟合,迭代 n_steps
6. 取最优序列第一个动作,在真环境执行 → 新 s_{t+1};回到 1
```

**探测 6 只改第 3 步**:
```
3'. 每条候选动作序列:
      env.set_sim_state(s_t)              # 存档回当前状态
      用候选动作真的 step 模拟器 H 步 → 真实第 H 帧图像
      emb_H = encode(真实第H帧)            # 完美物理 + le-wm 真 encoder
      (下一条候选前再 set_sim_state(s_t) 读档)
```
cost、CEM、encoder 全部保持 le-wm 原样,**只有动力学被换成真模拟器**。

**判读(这是 le-wm 规划链路的上界)**:
- **换上真物理就成功** → 瓶颈就是**学到的预测器**,encoder + cost 够用。→ 动力学问题,多步预测 / TD-MPC 能救。
- **给了完美物理仍失败** → 连完美动力学都救不回来 → 瓶颈在 **encoder(回探测 3)或 cost(回探测 2)**。

**实现要点**:
- 需 MuJoCo `get_sim_state`/`set_sim_state` 反复从同一状态分叉。
- 代价:每个规划步 N×H 次模拟,很慢。**这是诊断不是部署**,跑几十个 episode 足够下结论。
- 渲染要与训练图像同分辨率/视角/预处理,否则 encoder OOD,污染结论。

**工作量**:大(模拟器在环 + 存读档管线)。**最后做**,且只在前面探测指向"动力学是真凶"时才值得做。

## 决策表:汇总定锅

把各探测结果填进去,结论基本唯一:

| 探测 | 结果 | 真正瓶颈 | 是否"le-wm 能力有限" | 后续方向 |
|---|---|---|---|---|
| 1 规划预算 | 拉爆就好 | 规划预算/solver | 否 | 更强 solver / actor warm-start |
| 2 cost单调 | 非单调 / 假谷 | cost(goal-image MSE) | 否 | 换 cost / goal 表示 |
| 3 线性探针 | 弱probe解不出 | **表征容量(encoder)** | **是,根本性** | 换更大 encoder / 更强表征(td_jepa 帮不上) |
| 4 BC对照 | BC也崩 | 数据/任务难度 | 否 | 补数据 / 换任务设定 |
| 5 多步开环 | k=1,2 发散 | 单步动力学(复合误差) | 是,可缓解 | num_preds>1 / TD-MPC |
| 6 oracle规划 | 换真物理就成 | 学到的预测器 | 是,可缓解 | TD 后继价值(改造 B) |
| 6 oracle规划 | 真物理仍失败 | encoder 或 cost | 见 2/3 | 回 2/3 |

**只有当探测 3 失败(表征),或探测 5+6 一致指向动力学(C 发散 + E 一换就成)时,才能说"le-wm 自身能力有限"**,且两种"有限"的解法完全不同:
- 表征型有限 → 加大/换 encoder,与 td_jepa 无关。
- 动力学型有限 → **正是 td_jepa 后继价值(TD-MPC)能补的洞**,此时融合才有据可依。

## 建议执行顺序

```
前置 sanity(任务/收敛/集成/分布内预测)
  → 探测1(规划预算,几乎免费)
  → 探测2(cost单调,便宜)
  → 探测4(BC对照,切开数据vs模型)
  → 探测3(线性探针,定表征)
  → 探测5(多步开环,定复合误差)
  → 探测6(oracle规划,最终判决,仅当前面指向动力学时)
```

每一步出结论后回填决策表;一旦某步明确定锅,后面更贵的探测可按需跳过。

---

## 实现注意

- 全程**不修改 le-wm 训练核心**(两损失 = 单步 MSE + SIGReg 不动);探测都是**只读 / 旁路**(冻结 encoder 做 probe、前向算 cost/误差、旁路替换规划动力学)。唯一需要训练的是探测 3 的 probe 和探测 4 的 BC,都是独立小模型。
- 所有图像预处理(分辨率/归一化/视角/frameskip)必须与 le-wm 训练时严格一致,否则 encoder OOD,所有结论失效。
- 真值状态、模拟器存读档来自 LIBERO/MuJoCo env,先确认具体字段名与 API 再动手。
